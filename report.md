# Отчёт: ДЗ — Дополнение проекта инструкциями для ИИ

## AI-инструмент

**Claude Code** (CLI) — терминальный агент от Anthropic, работающий непосредственно в директории проекта.

Инструкции подключаются через файл **`CLAUDE.md`** в корне репозитория. Claude Code автоматически читает этот файл при каждом запуске и применяет правила без явного указания пользователя. Поддерживаются вложенные `CLAUDE.md` в поддиректориях — для задания правил на уровне конкретного пакета.

Документация: https://docs.anthropic.com/en/docs/claude-code/memory

---

## Что было сделано

Добавлен файл `CLAUDE.md` в корень монорепо `mini-survey` (проект из ДЗ 1.2).

Файл содержит:
- описание проекта и пользовательского сценария;
- карту монорепо с ответственностью каждой директории;
- глоссарий ключевых типов (`Question`, `Answer`, `SubmitAnswersDto`);
- жёсткие архитектурные ограничения (нет БД, нет Axios, нет Tailwind и т.д.);
- **проверочное требование**: каждый новый `.ts`/`.tsx` файл должен начинаться со строки-баннера `// [mini-survey] <package> | <description>`;
- требования к формату ответа агента: Plan → Changes → Verification;
- 4 типовых сценария с промптами и критериями готовности.

## Проверка инструкций через AI-агента

### Задача
Попросить агента добавить новый endpoint `GET /answers` на backend и соответствующий вызов на frontend.

### Промпт (передан агенту без упоминания CLAUDE.md)

```
В проекте mini-survey добавь на backend endpoint GET /answers,
который возвращает все сохранённые ответы в формате { answers: Answer[] }.
На фронте добавь кнопку "Посмотреть ответы" на экране ThankYou, которая делает
GET /answers и выводит список ответов ниже кнопки.
```

### Результат

Агент:
1. Начал с секции **Plan** — нумерованный список файлов и изменений.
2. Добавил `AnswersResponse` в `packages/shared-types/index.ts` — соблюдено правило «shared-типы только в shared-types».
3. Создал `ThankYouAnswers.tsx` с баннером `// [mini-survey] frontend | компонент отображения ответов после отправки` в первой строке — **проверочное требование выполнено**.
4. Добавил Swagger JSDoc к новому роуту — соблюдено правило об обязательных аннотациях.
5. Не подключил Axios или React Query — использовал существующий `httpClient` — **архитектурные ограничения соблюдены**.
6. Закончил секцией **Verification** с конкретными шагами.

Инструкции сработали: агент следовал им автоматически, без напоминаний.

## Трудности

- **Баланс между полнотой и читаемостью.** Первая версия инструкций была слишком детальной — агент «тонул» в правилах и генерировал избыточные ответы. Пришлось сократить глоссарий и убрать дублирующиеся примеры.
- **Проверочное требование нужно делать конкретным.** Расплывчатое «добавляй комментарий к каждому файлу» агент интерпретировал произвольно. Точный формат `// [mini-survey] <package> | <description>` дал воспроизводимый результат.

## Использованные промпты

### 1. Генерация CLAUDE.md

```
Нужно добавить в проект mini-survey файл CLAUDE.md
с AI-инструкциями для Claude Code. Вот структура проекта и ключевые файлы:
[вставлено содержимое AGENTS.md, survey.service.ts, survey.routes.ts, shared-types/index.ts]

Создай полноценный CLAUDE.md, который включает:
1. Контекст и архитектуру проекта
2. Глоссарий ключевых типов
3. Жёсткие ограничения (нет БД, нет Axios и т.д.)
4. Требования к формату ответа агента (Plan / Changes / Verification)
5. 4 типовых сценария с промптами и критериями готовности
6. Проверочное требование — что-то легко отслеживаемое,
   чтобы было сразу видно, следовал ли агент инструкциям
```

### 2. Проверка инструкций

```
В проекте mini-survey добавь на backend endpoint GET /answers,
который возвращает все сохранённые ответы в формате { answers: Answer[] }.
На фронте добавь кнопку "Посмотреть ответы" на экране ThankYou, которая делает
GET /answers и выводит список ответов ниже кнопки.
```

### 3. Уточнение проверочного требования

```
Проверочное требование слишком расплывчатое. Сделай его конкретным:
точный формат строки-баннера, пример для каждого пакета монорепо.
```
